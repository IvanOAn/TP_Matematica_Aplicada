### 5. Motor matemático y criptográfico

Implementá un motor independiente de la interfaz gráfica.

Utilizá SHA-256 mediante Web Crypto API.

Para evitar ambigüedades criptográficas, aplicá separación de dominios entre hojas y nodos internos.

Definiciones:

**Hash de hoja:**

H_leaf = SHA256(0x00 || bytes_del_archivo)

**Hash de nodo interno:**

H_parent = SHA256(0x01 || hash_izquierdo || hash_derecho)

Donde `||` representa concatenación de bytes, no concatenación de cadenas hexadecimales.

Los hashes deben almacenarse como bytes y representarse en hexadecimal únicamente para su visualización.

Reglas de construcción:

1. Cada archivo cargado representa una hoja.
2. El orden de los archivos debe conservarse.
3. Cada hoja contiene el hash del contenido binario del archivo.
4. Los nodos intermedios contienen el hash de sus dos hijos.
5. La raíz representa criptográficamente el conjunto completo.
6. Si un nivel contiene una cantidad impar de nodos mayor que uno, duplicar el último hash para formar la última pareja.
7. Con una sola hoja, la raíz es el hash de esa hoja.
8. No construir un árbol si no hay archivos.
9. Documentar explícitamente la convención adoptada para niveles impares.

Implementá funciones reutilizables para:

- Calcular hashes de hojas.
- Calcular hashes de nodos internos.
- Construir el árbol.
- Obtener sus niveles.
- Obtener la raíz.
- Comparar dos árboles.
- Identificar nodos modificados.
- Generar información para el grafo.

Usá identificadores estables basados en la posición del nodo en cada nivel.

No utilices hashes como identificadores únicos de nodos, porque dos archivos idénticos pueden tener el mismo hash.

### 7. Simulación de alteración de archivos

Esta es la funcionalidad más importante del proyecto.

Implementá un módulo interactivo denominado **Laboratorio de Integridad**.

Flujo de funcionamiento:

1. El usuario carga varios archivos.
2. El sistema calcula sus hashes.
3. Construye el Árbol de Merkle.
4. Guarda la raíz original.
5. El usuario selecciona uno de los archivos.
6. El usuario elige una posición de byte válida.
7. La aplicación modifica un bit de ese byte mediante una operación XOR con una máscara de un solo bit.
8. El archivo original no debe modificarse.
9. El sistema recalcula el hash de la hoja afectada.
10. Recalcula los nodos ascendentes hasta llegar a la raíz.
11. Compara la raíz original con la nueva.
12. Resalta visualmente los nodos afectados.

**Animación:**

La aplicación debe mostrar la propagación del cambio paso a paso:

- Paso 1: byte modificado.
- Paso 2: hash de hoja modificado.
- Paso 3: hash del nodo padre modificado.
- Paso 4: propagación por niveles.
- Paso 5: raíz modificada.
- Paso 6: resultado de verificación.

Agregar botones:
- Iniciar simulación.
- Siguiente paso.
- Paso anterior.
- Reproducir animación.
- Reiniciar simulación.
- Restaurar estado original.

Los nodos afectados deben destacarse visualmente.

No simular resultados ficticios: todos los hashes deben surgir de operaciones SHA-256 reales.

Permitir comparar los hashes originales y modificados.

Para archivos vacíos, ofrecer una explicación de por qué no existe una posición de byte modificable y permitir seleccionar otro archivo.
